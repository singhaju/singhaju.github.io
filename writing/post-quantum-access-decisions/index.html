Signing access decisions for a post-quantum future

Why PQ-SCVA-MCK, a submitted paper, signs each Kubernetes access decision with post-quantum algorithms, and how it avoids paying that cost on every request.

  • Post-quantum
  • Kubernetes
  • Research

The public-key cryptography most systems use today, such as RSA and elliptic curves, could be broken by a large enough quantum computer. Nobody knows when one will exist. But security records are kept for years, and data sent today can be recorded now and decrypted later. In August 2024, NIST published its first post-quantum standards, including ML-KEM for key exchange and ML-DSA for signatures.

The problem

Large companies run many Kubernetes clusters, often in different security domains, and a workload in one domain calls a service in another. Existing designs often trust a central policy controller, or check only some of the policy records. The service that enforces the decision cannot check that every allow and deny rule for the request was really evaluated.

The idea

  • Every decision carries a proof of exactly which scope it covered, checked against the complete, committed set of rules.
  • The proof holds only what that decision needs: the evidence for an allow differs from the evidence for an explicit deny or a default deny.
  • Decisions are signed with ML-DSA, and keys are exchanged with ML-KEM.
  • The authorization state is anchored on a ledger every epoch, so a failure or a rollback cannot quietly widen permissions.

Not paying on every request

Post-quantum signatures are much larger than the ones they replace, and checking them on every request adds up. So the full check happens once: a verified decision is bound to the workload's session, and later requests use a lightweight check. The ledger is used per epoch, not per request. When rules or revocations change, only the affected cached decisions are thrown away.

What I built

A Go prototype on AWS EKS with ML-DSA signatures, ML-KEM key exchange, sparse Merkle trees and Hyperledger Fabric anchoring.

What I took from it

Moving to post-quantum cryptography is not only swapping one algorithm for another. Bigger signatures change where you can afford to check them, so the design has to change around them.

PQ-SCVA-MCK is submitted (venue shown once accepted). I am the 1st of 2 authors, with Prof. Somchart Fugkeaw. It is under review, so this post shows the idea, not results. More on the PQ-SCVA-MCK case page.
