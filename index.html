Under review · IEEE TDSC

FEDAC: zero-trust access checks that stay fast

Problem

In Kubernetes spread across several clusters and organisations, access roles are static, and adding strong sign-in and tamper-evident policies usually puts heavy work on every request.

What I did

I built the implementation in Go and Rust: a hub that checks the caller once and issues a short-lived pass for one service, and a sidecar that checks that pass locally on every call. I also re-implemented published designs and compared them with FEDAC on AWS EKS.

Result
  • 1.4 ms median authorization check
  • ~7,100 requests/s on AWS EKS
  • Paper under review

Measured on AWS EKS. FEDAC was compared with three re-implemented published designs (Heimdall, ZKP-CapBAC and Atalay); the full comparison is in the paper, which is under review.

U-HAP on Kubernetes: the API server sends each authorization request to the U-HAP webhook, which answers from a decision cache or a gate-aware index evaluator. An admin's policies go through a DSL loader that validates them, a graph builder that compiles them, and an in-memory graph registry.

Research · second author of 4 · presenter

Published · IEEE JCSSE 2026Best Paper Award

U-HAP: one place for every Kubernetes access rule

Problem

Kubernetes splits access rules across modules that do not know about each other, and its RBAC can grant but never deny, so no single place shows which rule wins.

What I did

With three co-authors, I co-developed the authorization webhook and its policy model in Python, checked that its decisions match Open Policy Agent, and presented the paper at JCSSE 2026 in Bangkok.

Result
  • Best Paper Award
  • ~2.7× faster to a first decision after a policy update (vs OPA, 2,000 policies)
  • Same decisions as OPA

Compared with Open Policy Agent on the same policies; the method and setup are in the published paper.

Problem

Outcome

MoCA: AI containment

First author

Keep a hijacked AI agent inside what its human allowed: an MCP gateway and resource-side checks

  • AI-agent security
  • Delegation and revocation
  • Prompt injection
  • Python
  • MCP tool gateway

In preparation

Private repository

Idea and what I built
The idea
Authority is checked when an action is committed, not when it is planned. Permissions can only shrink as one agent delegates to another, revocation can be verified, and text from untrusted sources, such as a web page with a hidden instruction, cannot trigger actions beyond its limit.
What I built
A Python reference implementation: an MCP tool gateway plus a second check at the resource, and a harness that replays prompt-injection and delegation attacks.
