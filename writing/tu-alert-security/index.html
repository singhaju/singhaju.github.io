Security from day one in a student-built campus app

How our team is building TU Alert for Thammasat University with roles, a second sign-in step for staff, data erasure tools and security scans on every change.

  • Application security
  • TypeScript
  • Project

TU Alert lets students report a safety problem, such as a fallen tree, a fire or an accident, inside LINE with photos and a map pin, and sends it to the office that owns it. Thammasat University hired a team to build it; I am the tech lead: I lead the team, design the architecture and the security, and write code too. It is launching soon.

Four roles

Access is split into four roles, so a student and a staff member see different tools.

A second step for staff

Staff accounts can see and change reports from many students, so staff sign in with a second step.

Data that can be removed

Reports can include photos and places. We built tools for data retention and erasure, and kill switches to turn features off quickly.

Checks on every change

  • Semgrep scans every change for risky code patterns.
  • gitleaks scans the full code history for leaked keys and passwords.
  • Unit, integration and Playwright end-to-end tests.
  • Nightly database backups with written restore steps.

What I learned

Adding these checks at the start was easier than adding them later: each new feature goes through the same scans and tests.

The code is private (client project). More on the TU Alert case page.
